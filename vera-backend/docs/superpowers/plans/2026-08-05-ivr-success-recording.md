# IVR Success Recording Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record, per call, whether the IVR navigator ran and when it reached a live human — the raw data for the VR2-45 "IVR Success %" metric (dashboard card ships later).

**Architecture:** Two frozen columns on `call` (`ivr_enabled` stamped by the dispatcher at call creation; `ivr_exited_at` stamped by the worker-event consumer when the navigator hands off to the verification agent). One new worker event `ivr.exited` carries the moment from the DB-less agent worker to the control plane over the existing Redis event bus.

**Tech Stack:** SQLAlchemy + Alembic (idempotent DDL), Pydantic discriminated-union worker events, existing `WorkerEventConsumer` handler registry, pytest (unit fakes — no live Redis/DB).

**Spec:** `vera-backend/docs/superpowers/specs/2026-08-05-ivr-success-recording-design.md`

## Global Constraints

- All work in `vera-backend/`; run commands from that directory.
- Comments: only where code cannot say it; one line; no narration (repo CLAUDE.md).
- Migrations: idempotent DDL (`ADD COLUMN IF NOT EXISTS`) — CI replays the chain from `0001` on a fresh DB where `create_all` already made the columns. Revision id must be alembic-generated (never hand-numbered); chain stays linear off the current head.
- Timestamps come from the DB clock (`func.now()`), never the app clock — repo audit-clock rule.
- `asyncio` only; PEP 695 generics; mypy --strict passes.
- Git: NO `Co-Authored-By: Claude` trailers (team rule). Commit after each task.
- Final gate before "done": `/simplify` on the diff, then `just check` verbatim (never a subset).
- The metric definition (documented in the spec, not implemented here):
  `success % = COUNT(ivr_exited_at IS NOT NULL) / COUNT(ivr_enabled AND started_at IS NOT NULL AND NOT (current_status='canceled' AND ivr_exited_at IS NULL))`
- The spec's integration test of that SQL ships with the dashboard-card PR (when the
  SQL becomes code in `analytics.py`) — this plan records the inputs only. Task 4's
  spec edit notes this alongside the clock change.

```python
    async def _handle_ivr_exited(self, event: WorkerEvent) -> None:
        """The navigator reached a live human — stamp the VR2-45 IVR Success
        numerator. DB clock (audit-clock rule); the NULL-guard makes Redis
        redelivery a no-op."""
        if not isinstance(event, IvrExitedEvent):
            return
        ref = parse_room_name(event.room_name)
        if ref is None:
            return  # non-vera / console room
        async with tenant_session(self._sessionmaker, ref.tenant_id) as session:
            call = (
                await session.execute(
                    select(Call).where(Call.id == ref.call_id).with_for_update()
                )
            ).scalar_one_or_none()
            if call is None:
                _retry_young_or_drop(event.room_name, event.ts)
                return  # voice-lab room, or the Call row hasn't committed yet
            if call.ivr_exited_at is None:
                call.ivr_exited_at = func.now()
```
