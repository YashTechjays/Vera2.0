# Infertility Schema Content Update (v1 → v2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update the `infertility_treatment` form schema's content (remove two fields, rename two field titles, add a hint, reorder + correct the Infertility Treatment section, group Diagnostic Testing's CPT codes under one ICD-10-coded parent, relocate one field) and publish it as a brand-new `SchemaVersion` row — while the current published version is preserved (demoted to `draft`, never deleted) so every `patient_form` already intake'd against it keeps resolving.

**Architecture:** This schema is **not** a hand-edited JSON/DB row — it's authored as typed Python in `vera_core/forms/catalog/ibv_standard.py` (`build_ibv_standard()`), compiled to `data/form_schemas/ibv_form_standard_v2.json` by `just compile-schemas`, and published into Postgres by `just seed-schemas` (`scripts/seed.py::_seed_form_schemas`). That seeding function is *already* the "add a new version, keep the old one" mechanism this task needs: it's keyed on the unique `insurance_type`, does an order-sensitive content diff, and — whenever the compiled JSON differs from what's currently published — demotes the currently-published `SchemaVersion` row to `status="draft"` (never deletes it) and inserts a new row at `version = max(version) + 1` with `status="published"`. The partial unique index `uq_schema_version_published_per_schema` guarantees exactly one published row at a time; `patient_form.schema_version_id` is a `RESTRICT` FK, so an old version can never be deleted out from under a form that's pinned to it. **No Alembic migration is needed** — this is a content change to the existing `infertility_treatment` family, not a new insurance type (that would need a DB CHECK-constraint migration; not the case here).

**Tech Stack:** Python 3.12, Pydantic v2 (`vera_core.forms.dsl`), SQLAlchemy async + Postgres, pytest, `just` task runner.

## Global Constraints

- **Never hand-edit `data/form_schemas/ibv_form_standard_v2.json`** — it's generated by `just compile-schemas` from `catalog/ibv_standard.py`. The freshness test (`tests/unit/forms/test_schema_dsl.py::TestCompiledArtifacts::test_committed_artifact_is_fresh`) fails CI on any drift.
- **Document key order IS field/section order.** `sections: dict[str, Section]` and `Section.fields: dict[str, FormField]` preserve Python dict insertion order, which becomes the voice-agent's question order. Reordering `_TREATMENTS`/field dicts is a real, intentional behavior change here, not cosmetic.
- **Reuse the authoring macros** in `vera_core/forms/authoring.py` (`enum_ask`, `text_ask`, `cpt_group`, `treatment_group`, `service_fields`, …) — don't hand-roll `Leaf`/`Group` dicts.
- **`inapplicable_value` is only legal where self or an ancestor carries `applicable_when`** (DSL validator rule) — not relevant to the edits here since no new gates are introduced, but keep it in mind if a step surprises you with a `ValidationError`.
- Every edit in this plan stays within the existing `infertility_treatment` `FormSchema` family (`insurance_type` unique constraint) — a "new version" here always means a new `SchemaVersion` row under the same `schema_id`, never a new `FormSchema` row.
- Per repo root `CLAUDE.md`: after the implementation is complete, run the **code-simplifier** agent ("simplify code") on the changed files before claiming done or committing, then re-run `just check`.
- Backend commands run from `vera-backend/` (this plan's file paths are relative to `vera-backend/` unless stated otherwise).

### Task 9: Prove the version-preservation guarantee end-to-end

**Files:**
- Modify: `tests/integration/db/test_seed_form_schemas.py`

**Interfaces:**
- Consumes: `_seed_form_schemas` (`scripts/seed.py`), `FormSchema`/`SchemaVersion`/`PatientForm`/`Tenant` models, `VersionStatus`/`InsuranceType` enums — all already imported or importable exactly as used in `tests/integration/db/test_promoted_fields_cleanup_migration.py` (reference for constructing a minimal `PatientForm`: only `tenant_id` and `schema_version_id` are required, the rest have defaults/are nullable).
- Produces: a new test, `test_seed_republishes_new_version_on_content_change_and_keeps_old_version_readable`, proving exactly the guarantee the requester asked for: the previously-published version is demoted to `draft` (never deleted), a new version is published, and a `patient_form` row created against the old version still resolves (its FK is intact, its `schema_json` is unchanged) after the reseed.

This test doesn't hardcode any of Tasks 2-7's specific field content — it seeds once, mutates the *in-memory* document dict returned by `build_ibv_standard()` (flip one leaf's `required` flag, the cheapest content-preserving-shape change) to simulate "the catalog changed", monkeypatches `_load_manifest` to return that mutated document, and reseeds. This way the test keeps proving the general mechanism regardless of what future content edits land in `ibv_standard.py`.

- [ ] **Step 1: Write the new test**

Add to `tests/integration/db/test_seed_form_schemas.py` (after the existing two tests, same file — add these imports at the top alongside the existing ones):

```python
from unittest.mock import patch

from vera_core.forms.catalog import SCHEMAS
from vera_core.forms.dsl import compile_document
from vera_core.models import PatientForm, Tenant

TENANT_SLUG = "seed-form-schemas-versioning-test"


async def test_seed_republishes_new_version_on_content_change_and_keeps_old_version_readable(
    admin_sessionmaker: async_sessionmaker[AsyncSession],
    clean_form_schemas: None,
) -> None:
    # Seed v1, then pin a patient_form to it (simulating an in-flight intake).
    async with admin_sessionmaker() as session, session.begin():
        await _seed_form_schemas(session)
    async with admin_sessionmaker() as session, session.begin():
        v1 = (
            await session.execute(
                select(SchemaVersion)
                .join(FormSchema, SchemaVersion.schema_id == FormSchema.id)
                .where(FormSchema.insurance_type == INSURANCE_TYPE)
            )
        ).scalar_one()
        tenant = Tenant(slug=TENANT_SLUG, name="Seed Versioning Test")
        session.add(tenant)
        await session.flush()
        pinned_form = PatientForm(tenant_id=tenant.id, schema_version_id=v1.id)
        session.add(pinned_form)
        await session.flush()
        v1_id, v1_json, pinned_form_id = v1.id, v1.schema_json, pinned_form.id

    # Simulate a content change: mutate the built document in-memory (flip one
    # leaf's `required` flag) and reseed through the same code path.
    _, build_fn = SCHEMAS[INSURANCE_TYPE]
    doc = build_fn()
    doc.sections["patient_information"].fields["patient_name"].required = False
    mutated = (INSURANCE_TYPE, doc.name, doc)

    with patch("scripts.seed._load_manifest", return_value=[mutated]):
        async with admin_sessionmaker() as session, session.begin():
            await _seed_form_schemas(session)

    async with admin_sessionmaker() as session:
        # Old version: preserved, demoted, content untouched, still FK-resolvable.
        v1_after = await session.get(SchemaVersion, v1_id)
        assert v1_after is not None
        assert v1_after.status == VersionStatus.DRAFT
        assert v1_after.schema_json == v1_json

        pinned_after = await session.get(PatientForm, pinned_form_id)
        assert pinned_after is not None
        assert pinned_after.schema_version_id == v1_id

        # New version: published, version incremented, content reflects the change.
        v2 = (
            await session.execute(
                select(SchemaVersion).where(
                    SchemaVersion.schema_id == v1.schema_id,
                    SchemaVersion.status == VersionStatus.PUBLISHED,
                )
            )
        ).scalar_one()
        assert v2.version == v1.version + 1
        assert v2.id != v1_id
        assert compile_document(doc) == compile_document(doc)  # sanity: doc still loads/compiles
```
