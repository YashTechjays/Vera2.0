# Remove `prerequisite_fields` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete the `prerequisite_fields` concept from the form-schema DSL entirely (grammar, validator, the one catalog module that used it, and all its frontend UI-color plumbing), and publish the result as a new `SchemaVersion` — because it is redundant: every path it currently names for `infertility_treatment` (`appointment_date`, `appointment_type`, `callback_number`) is already a `system_fields` target, and `prerequisite_fields` has zero runtime/behavioral effect anywhere in the codebase — its only two effects are a backend structural validator check (path must resolve to a leaf) and a frontend cosmetic amber highlight + legend entry that would otherwise just render as the (correct, already-informative) `system` violet highlight.

**Architecture:** Same versioning mechanism as prior schema-content changes on this branch: edit the Python catalog source (`ibv_standard.py`), recompile the JSON artifact (`just compile-schemas`), publish via `just seed-schemas` (old `SchemaVersion` demoted to `draft`, never deleted; new version published). This is a DSL **grammar** removal (not just a content edit), so it also touches `dsl.py` (the Pydantic model + validator) and the frontend's mirror of that grammar (`types.ts`, `schema.ts`, `usageMeta.ts`) — nothing here needs an Alembic migration; `prerequisite_fields` was never a DB column, only a JSON-document key.

**Tech Stack:** Python 3.12, Pydantic v2 (`vera_core.forms.dsl`), TypeScript/Vitest (frontend `vera-frontend/src/lib/ibv`), `just` task runner.

## Global Constraints

- `prerequisite_fields` exists ONLY in `ibv_standard.py` (`infertility_treatment`) — `disease_only.py` never sets it (confirmed via grep: zero hits). No other catalog module needs touching.
- After removing the field from `dsl.py`, `FormSchemaDoc` objects that don't set it simply won't have the attribute — there is no backward-compatibility shim to write; old, already-published `SchemaVersion` rows (v1/v2/v3, all `draft` except the current published one) are stored JSON blobs and are never re-validated against the current Pydantic model, so removing the field from the grammar cannot break them.
- Per repo root `CLAUDE.md`: after the implementation is complete, run the **code-simplifier** agent ("simplify code") on the changed files before claiming done or committing, then re-run `just check` (backend) and `tsc`/`vitest` (frontend).
- Backend commands run from `vera-backend/`, frontend commands from `vera-frontend/` (paths below are relative to whichever directory each task specifies).
- This is a real, intentional content-shape change to the compiled artifact (the `prerequisite_fields` key disappears from `ibv_form_standard_v2.json` entirely) — it requires a new `SchemaVersion` publish exactly like the prior plan's changes did, via the same `just compile-schemas` + `just seed-schemas` path (never an Alembic migration).

```ts
 * How a leaf participates in the voice call — drives the UI color coding:
 * - `system`: bound in `system_fields` — the platform itself reads/writes it
 *   (worklists, integrations, call setup); takes precedence over the role.
 * - `context`: fed to the voice agent as known background (role context).
 * - `noop`: UI-only — never in the prompt, never asked (role input/readonly).
 * - `asked`: collected on the call (role ask/confirm).
 */
export type FieldUsage = "prerequisite" | "system" | "context" | "noop" | "asked"

const _systemPathsBySchema = new WeakMap<FormSchema, Set<string>>()

/** The field paths bound to well-known system handles (`system_fields`). */
export function systemFieldPaths(schema: FormSchema): Set<string> {
  let paths = _systemPathsBySchema.get(schema)
  if (!paths) {
    paths = new Set(Object.values(schema.system_fields ?? {}))
    _systemPathsBySchema.set(schema, paths)
  }
  return paths
}

const _prerequisitePathsBySchema = new WeakMap<FormSchema, Set<string>>()

/** The field paths listed in `prerequisite_fields` (call-prerequisite UI annotation). */
export function prerequisiteFieldPaths(schema: FormSchema): Set<string> {
  let paths = _prerequisitePathsBySchema.get(schema)
  if (!paths) {
    paths = new Set(schema.prerequisite_fields ?? [])
    _prerequisitePathsBySchema.set(schema, paths)
  }
  return paths
}

export function fieldUsageOf(
  schema: FormSchema,
  path: string,
  field: LeafField
): FieldUsage {
  if (prerequisiteFieldPaths(schema).has(path)) return "prerequisite"
  if (systemFieldPaths(schema).has(path)) return "system"
  // A ui_only SECTION is never voice-touched, whatever its leaves' roles say.
  if (schema.sections[path.split(".")[1]]?.role === "ui_only") return "noop"
  if (field.role === "context") return "context"
  if (field.role === "input" || field.role === "readonly") return "noop"
  return "asked"
```
